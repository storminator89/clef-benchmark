# Separate finance / insurance-broker text experiment

This is a separate extension: 80 synthetic German primary scenarios plus 20
selected English translations, in eight categories with five labels each. Its
100 requests, policies, gold labels, freeze, scores and results are independent
of the original 180-request benchmark. No pooled headline score is defined.
Both experiments evaluate text only; no images, OCR or multimodal performance
are evaluated in this release.

The test checks classification against invented policies. It does not determine
real insurance eligibility, creditworthiness, legal validity, compliance,
product suitability, or permission to execute a financial/contract action.
No real client, health, asset, policy or account data is included. See
[the complete methodology](../finance_benchmark/README.md).

## Same model configuration, separate inputs and outputs

The extension uses the same pinned Clef-flash revision, original native head,
experimental CPU NF4/BF16 configuration and unmodified `runtime/run_clef.py`
runner described in [REPRODUCIBILITY.md](REPRODUCIBILITY.md). The model's seed
is 20261002; the finance request-order shuffle seed is separately 2026100202.
Do not confuse the two. The extension was finalized before its own inference,
after the original experiment had completed. Its review was blind to finance
outputs, not to all preceding results.

After the one-time environment setup and exact model download:

```sh
bash runtime/reproduce_finance.sh
```

Run only one full model process at a time on a constrained CPU machine. This
script writes `runtime/reproduced_finance_predictions.jsonl`, its completed
metadata, and `runtime/reproduced_finance_scores.json`. Existing predictions
are never overwritten. It never modifies the published `results/finance/`.

To validate data and re-score without inference:

```sh
python3 finance_benchmark/validate.py
python3 finance_benchmark/score.py results/finance/predictions.jsonl --out /tmp/finance_rescored.json
python3 scripts/check_project.py
```

The scorer is independently versioned as `finance-broker-1.0`. The frozen
validator includes synthetic scorer fixtures, deterministic reconstruction,
pair alignment and metadata-isolation checks. Synthetic fixtures establish
software behavior only. The final complete recorded run is independently
verified and stored with its own hashes.

## Interpret English controls carefully

The English control set supports only two or three of the five policy labels
per category. All-policy-label macro-F1 assigns absent classes F1=0; even
perfect English predictions yield category values of 0.4 or 0.6 and an overall
category-average value of 0.5. The additional observed-support variant excludes
gold classes with zero support. Neither is a direct comparison with all 80
German cases. Use accuracy on the same 20 DE/EN pairs for a language comparison,
and retain the limitations of a small purposively selected sample.

The tests use no mixed-language schema variant in this extension. Differences
between DE/DE and EN/EN therefore combine the input, policy and label-description
languages; they do not isolate a causal language effect.

## Published artifact layout

- `finance_benchmark/`: byte-identical final frozen data, policies, generator,
  validator, scorer, public pre-inference QA, encoding preflight and manifest
- `results/finance/predictions.jsonl`: all 100 original model responses
- `results/finance/run_metadata.json`: completed run identity and configuration
- `results/finance/scores.json`: public path-only derivative of the score report
- `results/finance/verification.json`: independent final metric verification
- `results/finance/summary.json`: compact post-hoc summary, regenerated by
  `scripts/summarize_finance_results.py`; no raw predictions or metrics modified
- `docs/FINANCE_FINDINGS.md`: public independently checked findings and limits
- `provenance/curation_manifest.json`: original/public hashes and explicit
  transformations; no model decisions or metric values changed for publication

The full package checker also regenerates both compact summaries in temporary
directories and requires byte-identical output.

The original benchmark remains in `benchmark/` and its outputs in `results/`.
The separately recorded technical live-adapter smoke test under `qa/` is excluded
from both benchmark totals.
