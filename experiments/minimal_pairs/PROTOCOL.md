# Pre-inference protocol: German minimal-change paired test

## Purpose and finite design

24 deliberately authored base situations, each with two variants: 48 German closed-rule cases. Eight pairs each in banking, insurance and finance. In each domain: one yes-to-no, one no-to-yes, one clarify-to-answer and one answer-to-clarify pair; four outcome-invariant pairs (two irrelevant-text edits, one fact changed within the same outcome region, one short-circuit sufficient-information control). Thus 12 flip and 12 invariant pairs. Each case has its own stateless model request. All 48 cases are run once in a fixed seeded shuffled order; pairs are not presented together or described as pairs to the model.

Each pair changes exactly one documented contiguous message span. The untouched rule, question, schema/options and message prefix/suffix are explicit and machine-checked. Paired metadata records the changed fact, span offsets and unchanged-prefix/suffix hashes. This bounds textual change; it does not claim a general causal estimate. Some invariant edits change relevant facts without crossing the decision boundary. Three controls turn an unknown conjunct into a satisfied conjunct while a different necessary conjunct remains false. Stable wrong answers are never counted as both-correct.

Scenarios/rules/gold are AI-authored; every pair and both cases receive separate pre-inference AI review with gold visibility. This is not human-expert validation or a held-out representative population sample. The prior clarification72 exact two-field schema, English option IDs and generic conjunction/threshold/uncertainty patterns are intentionally reused; all 24 situation and rule texts are newly authored. No previous score is pooled with this suite.

## Model-visible input and freeze

Only data/requests.jsonl enters native inference. It contains fictional German rules, scenario text, question, and the inherited action/determination schema. IDs are logging-only and not encoded prompt text. Gold, rationale, domain, kind, family and pair structure stay outside model requests. Gold outputs use action = answer / ask_fact / ask_target / resolve_conflict and determination = yes / no / unresolved. Option and field order are constant and frozen. The official English encoding wrapper remains unchanged.

Before model load: independent case/pair review and retained correction history; dataset validation; scorer mutation/self-tests; exact uncapped-versus-2048-cap token equality for every input; complete model/source checksums and runtime package verification; then hash all requests, gold, pair metadata, order, scorer, protocol and runtime reference sources. No benchmark inference before freeze. No outcome-driven prompt/gold changes, retry-selection, option shuffling, exclusion or model retuning afterward. Any interrupted/partial execution remains a separate transparent partial result.

## Preregistered metrics

- Case exactness: both native fields correct, denominator 48. Individual field accuracy also /48; 96 field decisions are descriptive dependent values.
- Pair both-correct: both cases each have both fields correct, denominator 24. Also report by pair kind/domain/subtype, with counts.
- Correct directional change on flip pairs: predicted complete two-field endpoint A equals gold A AND endpoint B equals gold B, denominator 12. This intentionally equals both-correct restricted to flip pairs; a mere output change is insufficient. Also report observed changes and wrong/missing directional transitions separately.
- Unjustified change on invariant pairs: both outputs technically valid but at least one predicted field differs across A/B, denominator 12. Report the valid-pair conditional rate too. Invalid/missing endpoints are separately counted and are never credited as stable; failed invariance = observed unjustified change OR invalid/missing endpoint, denominator 12.
- Stable invariant pairs: both endpoints valid and their full output is identical, /12. Separately identify stable-but-not-both-correct pairs. These stability measures alone do not imply correctness.

All metrics retain the fixed finite-set denominators. Missing/invalid predictions score incorrect in case and pair correctness; duplicate/unexpected prediction IDs stop scoring rather than choosing a row. Native answers must match the original argmax (including criterion-order tie-breaking), native rounded per-option maps must equal round(unrounded_probability,4) for every option, full unrounded probability maps must match all options and sum to one within 1e-5, and the native rounded confidence must match the selected probability within 0.00011. Invalid fields (including absent/malformed/inconsistent native rounded maps), tokens/truncation or telemetry invalidate the entire case. Invalid pairs are shown explicitly alongside stability rates so failure cannot look like improved stability. Every error case retains its full rule/message/question/gold/prediction and all native probabilities; all erroneous pairs are listed.

## Runtime and retained evidence

Official 9B Cloudflare/clef-flash revision 17f0b0ad64efb65d273590632833508766b2aae6; unmodified native model code and original run_clef.py SHA256 d06f85b922e1e4d0e905a1ddc8846aedcafa93c29f502f48b1529a36a9eb5906. CPU NF4 backbone with double quantization, BF16 computation, original BF16 joint head/output embeddings; six threads, batch1, cap2048, seed20261002. Torch2.11.0+cpu / Transformers5.10.2 / bitsandbytes0.50.2; all dependency/model/source facts retained. Exclusive model loading with RAM guard. No GPU, native unquantized precision or stock serving claim.

Record every request's original native answers, complete unrounded option scores, token counts, encoding/forward/total seconds and process RSS. The unmodified runner makes one unrelated technical warmup and repeats its first benchmark case once afterward. Both are excluded from quality and latency aggregates. The warmup native result and runner's repeatability summary are retained; the runner does not expose the repeat's full separate vector/timing and that is not invented. One single-case identical probe cannot establish broad deterministic reproducibility. Marginal scores are neither calibrated nor joint probabilities.

## Audit, release and limits

An independently implemented post-run score/integrity checker must not import the primary scorer. It checks every native row, every pair, all metrics, errors, hashes and freeze chronology. Public export preserves all cases, predictions, probabilities, timings, errors and public-essential runtime facts; only private host paths/hostnames/PIDs/host-memory-availability/loader diagnostics are omitted or transformed, with a manifest and checksums. Original private evidence remains intact. Public verification and ZIP extraction must pass before handoff to the separate publisher.

No naive independent-case significance tests or population claims: two members of each pair are dependent, and schema/pattern reuse makes cross-pair independence implausible. This tests bounded native choices, not generated German answer or question quality, real product terms, real customers, financial advice or actual transactions. Subtype×domain cells contain only one pair each, except irrelevant-text cells with two pairs. Clarify-to-answer endpoints and answer-to-clarify start labels are not perfectly balanced across three domains. All three short-circuit controls are necessarily no/no under the chosen conjunctive rules. A later probability reliability analysis may use these locked predictions only after final audit and under its own analysis plan.
