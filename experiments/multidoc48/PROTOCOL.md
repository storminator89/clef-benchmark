# Preregistered protocol: German multi-document precedence

## Scientific question and finite design

Can the native bounded-choice model select a complete governing source and its yes/no result using explicitly supplied authority, applicability and scope rules? The new synthetic dataset contains 48 stateless German requests, 16 each in banking, insurance and finance. Every request presents exactly three short fictional documents, known facts and one customer question. There are four primary strata (12 cases each): authority hierarchy, effective-date applicability, scope/specific rules, and unresolved source choice. Twelve domain×stratum families reuse sixteen structural templates across the three domains. Explicit template_id fields retain that cross-domain dependence; the twelve family groups are not independent clusters. Cases are therefore related, not independently sampled or independently written situations. No significance tests or population generalization are planned.

Gold outcomes are 18 yes, 18 no, 12 unresolved. Twenty-seven cases have a unique governing document; its identifier is D1/D2/D3 nine times each and its displayed ordinal position is first/second/third nine times each. Each identifier and position occurs four times among unique-source yes cases and five times among unique-source no cases. Twenty-one cases have no unique source; twelve of those need material clarification and nine have a definite answer because all plausible sources agree. Those nine are important negative controls: unknown source does not automatically require an unresolved outcome. All cases contain three documents so document count cannot distinguish these groups.

Document selection, not composition, is tested: each source gives a complete threshold rule; narrower applicable rules replace the base rule completely. No clause-merging capability is claimed. These are invented closed-world rules, not real banking terms, insurance coverage, financial advice or legal facts. No customer data or transactions are involved.

## Native fields and input isolation

The fields are source = D1 / D2 / D3 / not_unique and determination = yes / no / unresolved. not_unique means at least two documents remain possible as the sole complete governing source. It does not mean their outcomes disagree. unresolved means the available facts permit both yes and no; it is the bounded marker for material clarification, not a generated follow-up question. The field option order is fixed. Document order and execution order use a predeclared seed, 2026100204, followed by pre-outcome counterbalancing of unique-source labels and positions. IDs are logging-only and not encoded as case IDs; source IDs necessarily appear in documents and the source schema.

Only data/requests.jsonl reaches the model. It includes the fictional source text, all precedence/applicability rules, known facts, question and schema. Gold, rationales, domains, family/subtype labels, plausible-source metadata and expected outcomes are stored separately. A source selection can be unknown while determination is definite; never label this combination inconsistent merely because it is mixed.

## Review, corrections and freeze

All documents, cases, gold, applicability evidence and plausible-source sets undergo separate AI review before model loading. This is AI-authored and independently AI-reviewed, not human-expert validation. Pre-run review corrections are retained with old and new public scientific hashes; corrections do not use model predictions. Primary and independently implemented scorers are tested on synthetic complete, missing, malformed, inconsistent and duplicate/unexpected outputs, including fixed denominators. All requests are encoded with the original native encoder both uncapped and at 2048 tokens; exact token-list equality is mandatory. No truncation or prompt manipulation is allowed.

Freeze requests, gold, cases, metadata, policy, order, scoring/checker code, protocol, preflight, review, runtime reference files and package/model/source verification before any inference. No post-outcome prompt tuning, gold repair, option shuffling, selective retries, case exclusions or score selection. Any interrupted execution remains transparently partial under this identity. No matched order-swap experiment is planned: positional balance is a design control, not evidence of causal order robustness. No post-hoc rerunning of mistakes with swapped documents.

## Fixed metrics and technical validity

1. Both-fields exact /48; source correct /48; determination correct /48; correct field decisions /96. These are dependent descriptive counts, not independent trials.
2. Unique-source correct /27, wrong concrete source /27, unnecessary source uncertainty /27; correctly unresolved source /21, invented unique source /21. All-field exactness on the nine same-answer ambiguous-source controls is reported /9.
3. Missed material clarification /12; excess clarification /36; wrong opposite definite answer on answerable cases /36. Missing/invalid outputs are reported separately on each eligible subset. Invalid outputs are never counted as successful clarification or a valid concrete error.
4. Per-domain, stratum, family, shared-template (template_id) and subtype exactness and field correctness with explicit denominators. The effective-date and scope strata isolate their source-selection errors descriptively, without claiming a unique psychological cause.
5. Rule-based field-pair inconsistency /48: a concrete selected source is absent or its own complete rule contradicts the predicted determination; or source=not_unique and determination is definite on a gold material-source-ambiguity case. not_unique with a definite answer on the nine same-answer controls is valid. This is a constrained rule-based diagnostic, not a general model reasoning assessment.

Every missing or technically invalid case scores wrong on both fields and exactness using the full fixed denominator. Duplicate or unexpected prediction IDs halt scoring. Native outputs must contain the exact fields and all option probabilities. Unrounded values must be numeric, finite, within [0,1], and sum to one within 1e-5. The choice must equal the native argmax, ties resolved by frozen criterion order. Rounded native maps must equal round(unrounded,4) for every option; confidence must exactly equal round(selected_probability,4) and remain finite within [0,1]. The entire case is invalid if any field, map, choice, token/truncation declaration or required nonnegative telemetry is absent/malformed. Native source IDs that are choices but refer to an absent document are semantic errors, not parsing failures (all current cases have all three IDs).

Quality and timing summaries exclude the runner's unrelated warmup and its first-case repeated probe. Keep every actual benchmark prediction, field/option score, token count, encoding/forward/total time, memory reading, failure and completion status. Report valid and missing/invalid denominators so technical failure cannot appear to reduce risky answer rates. Forward-time median, interpolated p95, sum, input-token range and observed maximum process RSS describe this run, not general serving capacity.
